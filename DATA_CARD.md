# Data card

## Provider

US Securities and Exchange Commission, EDGAR data APIs.

- Company facts: `https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json` (all XBRL facts for one registrant, keyed by taxonomy, tag and unit).
- Submissions: `https://data.sec.gov/submissions/CIK##########.json` (filing index for one registrant: accession numbers, forms, filing dates).
- Documentation: https://www.sec.gov/edgar/sec-api-documentation

## Terms and access

- Terms: https://www.sec.gov/os/accessing-edgar-data (fair access policy). `make fetch` prints this URL before doing anything else.
- No API key exists. Access is anonymous but must declare a descriptive `User-Agent` naming the requester and a contact address. This client takes it from the `SEC_USER_AGENT` environment variable and refuses to run without it (exit code 2).
- Rate limit: at most 10 requests per second. `RateLimiter` sleeps between calls to stay under it.
- No CORS headers are sent by `data.sec.gov`, so a browser page cannot call the API directly; a server-side or command-line client such as this one is required.
- The APIs are updated by the SEC in near real time; a cached copy is a snapshot. Every cache entry records `retrieved_at` and a `sha256` of the payload.

## What is and is not in this repository

- No real company data is shipped. `cache/` is git-ignored.
- `examples/fixtures/v1/` holds authored synthetic companyfacts and submissions documents for three fictional issuers (Northwind Demo Corp, Bluewater Demo Holdings, Granite Demo Industries; CIKs 9999999001 to 9999999003). See `examples/fixtures/v1/FIXTURE.md`. Generated by `tools/make_fixture.py`, seed 42.
- There is no fraud label dataset and no fraud classifier. Review flags are threshold rules on ratios.

## Record unit

One fact: a value reported for one XBRL tag, in one unit, for one period (a duration with start and end, or an instant with only an end), by one filing (accession number, form, filing date). A single quantity is usually reported by several filings; see `docs/method.md` for how one is selected.

## Columns (companyfacts rows)

| Field | Meaning |
|---|---|
| `start`, `end` | period dates (ISO); `start` absent for instants |
| `val` | reported value; USD values are whole dollars and are stored as integers |
| `accn` | accession number `0000000000-YY-NNNNNN` |
| `fy`, `fp` | fiscal year and period of the *filing* (a comparative column carries the later filing's fy) |
| `form` | `10-K`, `10-Q`, `10-K/A`, ... |
| `filed` | filing date (ISO); the basis for point-in-time selection |
| `frame` | SEC calendar frame such as `CY2023`, `CY2023Q1`, `CY2023Q4I` (optional) |

## Target

None. This is an analysis and provenance tool, not a supervised task.

## Splits

Not applicable in the machine-learning sense. The analysis date D acts as the temporal boundary: only facts filed on or before D are used, and a test perturbs every later-filed fact to prove the output does not change.

## Missingness

Tags differ between filers. A concept with no matching tag yields a ratio with `value: null` and a `reason` string. The Bluewater fixture omits operating cash flow for FY2021 and has no `DebtCurrent` tag to exercise this path.

## Known caveats of the source

- Amendments (10-K/A) restate values for periods already reported; the later filing date decides which value is current.
- Fiscal years are not calendar years for many registrants; grouping keys on period end date.
- Some tags are reported in units other than USD (`shares`, `pure`, `USD/shares`). Money ratios use USD facts only.
